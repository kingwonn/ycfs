# 具身大脑 / 本体厂商:对数据与数采设备的硬要求

> 从他们训练管线的实际输入规格倒推,不是从"客户大概想要什么"猜。
> 数字来自公开论文与数据集文档,标 `[有据]`;由要求倒推出的设备含义标 `[倒推]`。

---

## 零、先说最重要的发现:UMI 与第一梯队 VLA 之间有结构性鸿沟

把 π0 的输入要求和 UMI 的输出能力并排放:

| π0 要求 `[有据]` | UMI 实际提供 | 差距 |
|---|---|---|
| 关节状态轨迹 **≥50 Hz** | 末端位姿,受相机帧率限制(常 30–60fps) | 频率 + **类型都不对** |
| **硬件触发帧同步,亚毫秒级对齐**(action chunk 训练的严格要求) | 单个 GoPro + 软件/IMU 对齐 | **结构性做不到** |
| 本体感知(joint state / torque) | **没有关节角——因为没有机器人** | 缺一整个模态 |
| 2–3 路相机同步 | 单腕视角 | 视角数不足 |

**那 RDT2 为什么能成?** 因为 RDT2 是**专门为 UMI 数据训的自家基座**,
模型侧做了适配。**不是拿 UMI 数据去喂 π0。**

> **推论(这可能是整个生意的命门):UMI 数据不是一件"通用可卖的商品"。**
> 它需要模型侧配套。卖给一个用 π0 式架构、要 50Hz 关节轨迹 + 亚毫秒同步的客户,
> **在格式层面就对不上,不是质量好坏的问题。**

这条比上一轮的 32.5% IK 问题严重得多——IK 是可用率问题,这是**能不能用**的问题。

## 一、两类客户,要的东西不一样

| | 大脑厂商(训通用基座) | 本体厂商(训自家机器人策略) |
|---|---|---|
| 核心诉求 | 规模 + 多样性 + 跨本体泛化 | **匹配自己本体**的关节/力/触觉 |
| 动作空间 | 可容忍 EE pose,愿做适配 | 要自己机器人的 joint state |
| 模态 | RGB 多视角 + 本体感知 | RGB-D + 触觉 + 力 + LiDAR + 全身关节 |
| 对 UMI 数据 | **有可能吃**(需自己适配) | **基本吃不下**(缺太多模态) |

**样板:智元 AgiBot World 2026** `[有据]` ——基于精灵 G2(工业级、高精度力控),
配 Swift Picker 夹爪 + OmniHand 五指灵巧手,**同步采集多视角 RGB(D)、触觉、
LiDAR 点云、IMU、全身关节状态、力传感器**,并用数字孪生 1:1 重建做仿真数据。

拿这个当标尺:**一个 GoPro + 夹爪编码器,和本体厂商的采集标准不在一个量级。**

## 二、对数据的硬要求(可直接写进规格书的数字)

### 2.1 采样与同步 `[有据]`

| 项 | 要求 | 出处 |
|---|---|---|
| 关节/动作频率 | **π0:≥50 Hz** 连续密集轨迹(非 RT-1/RT-2 的 3Hz 离散) | π0 |
| 遥操作控制频率 | GR00T:20 Hz;电机控制 120 Hz | GR00T |
| 视觉帧率 | 30 fps 为主流 | LeRobot |
| VLA 训练统一频率 | 常重采样到 10 Hz | LeRobot 实践 |
| **跨模态同步** | **硬件触发,亚毫秒级** | π0(明确称为严格要求) |

> **亚毫秒硬件同步是最硬的一条门槛,也是消费级相机方案的死穴。**

### 2.2 视觉 `[有据]`
- 分辨率 ≥ 640×480 / 720p;**实际 72% 的 LeRobot 数据集用 640×480 @ 30fps**
- 多视角:top-view / main-view / **wrist-view** 三类为典型组合
- 高端要求 RGB**-D**(AgiBot 标准)

### 2.3 动作与状态空间 `[有据]`
- 典型本体感知向量:**8 维 = 7 关节位置 + 1 夹爪状态**
- 动作标签同样 8 维控制指令
- π0 接受 joint position **或** end-effector delta,但要求连续、高频

### 2.4 语言与元数据 `[有据]`
- **自然语言任务描述是必需项**(用于语言条件策略与数据筛选)
- 元数据需含:本体规格、采集帧率、传感器类型、任务标注、统计量

### 2.5 存储格式 `[有据]`
- **LeRobotDataset**:`data/` 存每 episode 的 Parquet 时序表,`meta/` 存 schema、索引、任务标注、统计
- v3.0 支持大规模数据集
- 其他可接受:RLDS / Open X-Embodiment

## 三、质量判据(这是唯一能卖出溢价的地方)`[有据]`

研究结论很硬:**一致性 > 数量。**

> 「1 万条不一致或执行糟糕的演示,训出的策略就是不一致、执行糟糕的。」
> 「混合质量数据训出的模型,比小而一致的高质量数据更差。」

可量化的质量指标(**这些就是你的产品规格**):

| 指标 | 定义 | 怎么测 |
|---|---|---|
| **Tremble score(抖动)** | 实际速度轨迹 vs 平滑后轨迹的偏差 | 可自动计算 |
| **缺帧 / 缺相机率** | episode 内丢失的帧与视角 | 自动 |
| **时长异常** | 过短(没做完)或异常长(卡顿/重试) | 分布检测 |
| **运动量不足** | 静止占比过高的 episode | 阈值 |
| **一致性** | 同任务的轨迹是同一动作的变体,还是散乱的不同方法 | 轨迹聚类 |
| **场景/物体多样性** | 覆盖广度 | 计数 + 分布 |
| 位姿漂移 | 长 episode 的 VIO/SLAM 累积误差 | 回环检测 |

注:**多样性与一致性是一对张力。**"同一任务内一致、跨任务/场景多样"才是对的组合,
不能只优化一边。

## 四、由数据要求倒推的设备要求 `[倒推]`

按重要性排序(不是按工程难度):

1. **硬件级时间同步**——必须有统一时钟或触发信号贯穿所有传感器。
   单 GoPro 方案在这里结构性失分。这是**否决项,不是加分项**。
2. **≥50 Hz 的动作输出**,且要能给出**关节空间或可靠映射到关节空间的量**,
   不能只给视觉推算的末端位姿。
3. **多视角**(至少腕视角 + 一路外部视角),内外参出厂标定并随数据交付。
4. **跨设备标定一致性**——量产生死线:第 30 台起内参漂了,数据就混不了池。
5. **实时质检**:tremble / 丢帧 / 静止占比 当场算,当场提示重采。
6. **原生输出 LeRobot 格式**(不是"提供转换脚本")。
7. 可选加分:RGB-D、力/触觉——本体厂商的门槛在这,大脑厂商暂不强求。

## 五、这份清单对生意的三条结论

1. **卖"UMI 原始数据"给第一梯队大脑厂商,格式层面就通不过。**
   要么你的客户是能自己做模型侧适配的(那是少数头部),
   要么你得把数据补齐到 joint-state + 硬同步(那就不再是 UMI 了)。

2. **本体厂商这条路更难,不是更容易。** AgiBot 的采集标准是
   RGB-D + 触觉 + LiDAR + 力 + 全身关节,一个手持夹爪够不着。

3. **唯一可能站得住的位置,是质量层而不是采集层。**
   第三节那些指标(tremble、一致性、多样性、缺帧、漂移)是**可自动计算、
   可写进合同、可对比竞品**的东西,而且行业公认"一致性比数量重要"。
   卖"经过质量认证的数据"比卖"采数据的设备"更有定价权。
