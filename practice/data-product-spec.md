# 数据产品定义 + 设备基本参数(从具身大脑第一性原理倒推)

> 推导方向固定:**大脑要学什么 → 因此需要什么数据 → 因此 UMI 设备的根本需求是什么
> → 因此每个参数是多少**。每个参数都能沿这条链向上追责;追不上去的参数不许存在。

---

# 第一层:具身大脑的第一性需求

大脑(VLA/基座模型)学的是一个条件分布:

```
π( 动作 | 观察, 语言, 状态 )
```

从这一行,数据的全部要求可以推干净:

**N1|成对且对齐。** 模型学的是"看到这个 → 做这个"的映射。观察与动作错位 = 给对的观察配错的动作 = **标签噪声**。时间错位不是工程瑕疵,是直接往训练信号里注毒。行业实测出现过 150ms 动作时间戳抖动 [有据]——在 60fps 下这是错位 9 帧。
→ **数据第一性要求:跨模态时间同步,且同步质量可证明。**

**N2|分布覆盖决定泛化。** 模型只能泛化到训练分布的邻域。场景/物体/光照/任务的多样性不是加分项,是泛化的**唯一来源** [有据:一致的行业结论]。多样性要求采集走出实验室、进入真实场所、由很多人采。
→ **数据要求:规模 × 多样性,且采集边际成本必须低。这一条就是 UMI 形态存在的根本原因。**

**N3|动作必须可执行。** 学到的动作若在目标本体的构型空间之外,策略在部署时物理不可行。公开报告:UMI 演示约 32.5% 因逆运动学不可行在放置阶段失败 [有据]。
→ **数据要求:每条轨迹带本体可行性信息(标注或重定向),embodiment gap 被管理而非被忽略。**

**N4|演示质量 = 策略天花板。** "1 万条不一致的演示训出不一致的策略;混合质量比小而一致更差" [有据]。抖动、过冲后修正、静止段,模型都会当成"该学的行为"学走。
→ **数据要求:一致性与操作质量可测量、可筛选(tremble、静止占比、轨迹聚类)。**

**N5|观察必须与部署同构。** 训练时的视角/畸变/分辨率若与机器人部署时不同,策略输入分布偏移。UMI 的腕装鱼眼之所以成立,是因为人演示与机器人执行的画面几乎不可区分 [有据]。
→ **数据要求:观察通道按部署形态设计,不按"拍得清楚"设计。**

**N6|接触物理只能来自真机。** 刚体引擎无法精确模拟弹性形变;接触动力学失配使力相关行为难以 sim2real [有据]。仿真成本是真机的 1% [有据]——所以**凡仿真能生成的,真机数据长期没有价格竞争力;真机数据的独有价值恰好就是仿真做不到的:接触力、触觉、真实物性**。
→ **数据要求:力/触觉与视觉/位姿同步采集——这是真机数据在经济上站得住的唯一支柱。**

# 第二层:压住——UMI 这类设备的根本需求到底是什么

UMI 的本质一句话:**把人的身体当作机器人,把人的演示转录成机器人可学的 (观察,动作) 序列。**

它存在的唯一理由:遥操真机太贵太慢(受机器人数量与场地限制,$118/h 仍是行业成本线 [有据]);仿真缺真实感知与接触(N6)。人不用培训、哪里都能去、演示天然流畅——**UMI 是把"人类身体的规模与灵巧"低成本转录进机器人数据的转换器。**

所以它的根本需求就是"转录不失真 + 转录得起量",压成五条(重要性排序):

| # | 根本需求 | 来自 | 一句话判据 |
|---|---|---|---|
| **R1** | **动作标签保真**:转录过程不引入假动作 | N1+N4 | 记录的轨迹 = 人真实做的轨迹(同步准、位姿准、无抖动伪影) |
| **R2** | **观察与部署同构** | N5 | 人演示画面与机器人执行画面难以区分 |
| **R3** | **规模与多样性的边际成本低** | N2 | 单人、便携、任意场所、开机即采、废品率低 |
| **R4** | **本体可迁移** | N3 | 每条轨迹知道"哪些机器人做得出" |
| **R5** | **仿真够不到的模态** | N6 | 接触力/触觉与其余模态同步 |

**压住的含义:任何不服务 R1–R5 的参数都是浪费。** 外观、超出需求的精度、炫技模态,一律砍。
下面每个参数后都标注它服务哪条 R、不达标会伤什么。

# 第三层:产品数据定义(这才是"产品"——设备只是它的生产工具)

交付物 = **LeRobot v3 原生数据包 + 质量证书**。schema 如下,每字段带"为什么"。

## 3.1 数据通道

| 通道 | 规格 | 服务 | 为什么是这个数 |
|---|---|---|---|
| `obs.wrist_rgb` | 腕装鱼眼 155°,**全局快门**,1280×960 @ **60fps**,硬件外触发 | R2,R1 | 155°/腕装=UMI 已验证的部署同构视角 [有据];全局快门:卷帘快门在快速手部运动下产生果冻畸变→几何失真同时伤视觉一致性与 VIO 精度;60fps:手部操作速度下 30fps 帧间位移过大,插值伤 R1 |
| `state.ee_pose` | 6-DoF,**200Hz**(VIO 60Hz + IMU 融合),相对精度 ≤2mm/≤0.5°,漂移 ≤5mm/episode | R1 | 200Hz 是 IMU 融合的自然输出率,给下游任意重采样留余量(π0 要 ≥50Hz [有据],交付时降采样而非升采样——**升采样=编造**);2mm:亚毫米超出操作任务需求=浪费(鹿明 1mm 是精度标杆但差异化不在此轴 [有据]) |
| `state.gripper` | 开合宽度,200Hz,分辨率 0.1mm | R1 | 与 ee_pose 同率,避免对齐插值 |
| `state.force` | **每指 3 轴力,≥500Hz**,量程 ±50N,分辨率 0.05N | R5 | 每指(非腕部单点):测量点靠近接触界面,惯性/重力补偿负担最小 [有据:UMI-FT 路线];500Hz:接触冲击瞬态在毫秒级,50Hz 只能看到"碰了",500Hz 才能看到"怎么碰的"——这正是仿真给不出的信息;±50N 覆盖家用/轻工操作 |
| `obs.tactile`(v1.1) | 2×指尖视触觉 30fps(DIGIT 路线,BOM $15 [有据]) | R5 | v1.0 留安装位与 schema 字段(恒 null),买家验证后上 |
| `lang.task` | 每 episode 自然语言任务描述,非模板 | N2 | 语言条件策略必需 [有据] |
| `meta.calib` | 相机内外参+畸变+标定日期+设备ID+同步自测报告 | R3 | 无标定档案的数据跨设备不能混池=规模化归零 |
| `meta.scene` | 场景/物体/光照标签 | N2 | 多样性可计量的前提 |

**明确不上的通道(压住,给理由):**
- **RGB-D 深度**:不上。深度是本体厂商采集标准(AgiBot 系 [有据]),但大脑训练主流输入是 RGB+本体感知;VIO 已提供几何;上深度增成本增重量伤 R3,收益无第一性依据。
- **腕部单点六维 F/T**:不上,被每指方案取代(补偿负担大、且分不开双指接触力)。
- **LiDAR/多外部相机阵列**:不上。那是场地方案,违背 R3 便携性。

## 3.2 动作标签交付(双格式,前文押注 3)

| 格式 | 内容 | 服务 |
|---|---|---|
| 原生 | EE 轨迹(200Hz 原始 + 50Hz 抗混叠降采样)+ 夹爪 | EE-pose 架构客户直接训 |
| 合成 | 客户 URDF 进 → IK 重定向 50Hz joint 轨迹 + **逐条可行性标注** | joint-state 架构客户;诚实条款:标明 synthetic,证书披露可行率 |

## 3.3 质量证书(每批数据随附,公式公开可复算)

十项:同步误差 P99 / 位姿漂移 / tremble / 丢帧率 / 时长异常率 / 静止占比 / 一致性聚类紧致度 / 多样性计数与熵 / IK 可行率(对指定本体)/ 溯源链完整性。
**证书是产品的一半:它把"数据好"从话术变成规格(R1/R3/R4 的可验证形态)。**

# 第四层:设备基本参数(生产上述数据的最小机器)

| 参数 | 值 | 服务 | 不达标伤什么 |
|---|---|---|---|
| **同步架构** | MCU 统一时钟 + 硬件触发总线直连相机/IMU/编码器/力传感,跨模态 **P99 ≤ 1ms**,每台出厂自测留档 | R1 | 同步是 N1 的物理承载;150ms 抖动=9 帧错位=标签噪声 [有据];这是与 GoPro 方案的代差、与消费级的分界 |
| **相机** | 全局快门鱼眼模组 1280×960@60fps,外触发引脚 | R1,R2 | 卷帘=运动畸变;无外触发=同步降级为软件对齐 |
| **位姿系统** | 双目+IMU VIO,融合 200Hz;episode 末回环优化;漂移 ≤5mm/episode | R1 | 漂移直接进动作标签;超标的 episode 证书标红 |
| **夹爪** | 平行爪行程 85mm,编码器 0.1mm,**可锁定机构**(TacUMI 路线 [有据]) | R1,R5 | 锁定后人手握力退出力测量——否则力通道被握力污染,R5 报废 |
| **力传感** | 每指 3 轴,≥500Hz,±50N,0.05N | R5 | 见 3.1;低于 500Hz 采不到冲击瞬态,力通道价值减半 |
| **重量** | **≤800g 目标,1kg 硬上限**(鹿明 FastUMI Pro 600g 级为参照 [有据]) | R3,**R1** | 重量不是舒适问题:手臂疲劳→演示变形→**一致性下降→N4 被伤**。超重直接毒化数据 |
| **续航/存储** | ≥4h 连续采集;1TB 本地(约一天量,对标 FastUMI Go [有据]) | R3 | 换电/倒数据的停机时间都是边际成本 |
| **开机到采集** | ≤60s(含自检);单手可换电池 | R3 | 现场每一分钟折腾都在抬高 $/有效小时 |
| **实时质检** | 机上运行:同步/丢帧/静止/tremble/可行性,**当场提示重采** | R3,R4 | 把 32.5% 废弃 [有据] 拦在现场——这是"有效小时"经济学的来源 |
| **标定一致性** | 出厂自动标定台;**同批设备内参偏差有量化上界**,档案随机身 | R3 | 第 30 台内参漂了→数据不能混池→规模化归零(单人硬件最常见死法) |
| **环境** | 室内外 100–100k lux;-10~40°C;无 IP 要求(v1 不进工业湿区) | R3 | 多样性要求走出实验室,但 IP 防护增重伤 R1,取舍偏 R1 |
| **BOM** | ≈¥7,300(力觉模块 ≤30%),目标零售 ¥15–20k 或成本铺量+订阅 | R3 | 高于遥操成本线即失去存在理由 |

## 参数否决线(哪条破了产品即不成立)

1. 同步 P99 > 5ms → R1 破,证书第一项失效,退回消费级阵营
2. 重量 > 1kg → R3/R1 双伤,长时采集数据质量不可控
3. 同批标定不一致 → 数据不能混池,规模叙事作废
4. 力通道被握力污染(锁定机构失效)→ R5 作废,产品退化为普通 UMI

# 原因分析总图(一页看懂"为什么是这台设备")

```
大脑学 π(a|o,l,s)
 ├─ N1 对齐 ────────→ R1 转录保真 ──→ 硬同步≤1ms / 全局快门 / VIO 200Hz / 锁定夹爪
 ├─ N2 覆盖 ────────→ R3 规模成本 ──→ ≤800g / 4h / 60s开机 / 现场质检 / 标定一致 / ¥7.3k
 ├─ N3 可执行 ──────→ R4 可迁移 ───→ URDF重定向 + 逐条可行性标注
 ├─ N4 一致性 ──────→ (证书: tremble/聚类/静止)
 ├─ N5 部署同构 ────→ R2 视角 ─────→ 腕装155°鱼眼
 └─ N6 接触物理 ────→ R5 独有模态 ─→ 每指3轴力500Hz(+触觉v1.1)
                                    ↑
                     仿真1%成本吃掉视觉/几何 → 真机数据的生存空间只剩这里
```

**一句话压住:这台设备不是"更好的 UMI",是"给大脑厂商的训练信号发生器"——
每个参数要么在保真(R1),要么在降本(R3),要么在采仿真采不到的东西(R5)。三者之外,皆是浪费。**
