# M2 数据可得性调查(2026-07)

> 研究 agent 带源。裁决:M2 分裂成两半——"力有没有用"可公开验,"力能否跨本体"是硬缺口。

## 结论一句话

**"力/触觉提升成功率"用公开数据+代码单卡可复现;"力能否跨本体迁移"公开资源不足,
基本必须自己采带力的跨本体数据。** 后者恰是产品的头号风险——所以最致命的那一半验不了。

## 两半裁决

**✅ 能公开验(离线,单卡):力有没有用**
- 首选 **RDP**(数据+代码+模型+mini 四要素齐全,单卡端到端跑通)
- 次选 **DexUMI**(唯一自带 `enable_fsr` 力开关,还有双手跨手对照)
- 多篇一致正向(FILIC +33~53pp、ForceMimic +54.5%、TacUMI 34%→75%)——**"力有用"这个方向证据已相当强**

**❌ 硬缺口:力能否跨本体迁移**
- 最大的跨本体数据(RDT2 UMI-10k、FastUMI-100K、OXE 主体)**全是纯视觉、无力**
- 真正"带力+跨本体"的只有 DexUMI 的小规模双手设置
- **"力信号能否跨本体迁移"没有现成大规模公开基准**——这正是产品最致命的论断

## 对产品与验证策略的直接影响

1. **M2 拆成 M2a(可做)+ M2b(缺口)**:
   - **M2a**:用 RDP/DexUMI 公开数据复算"力有没有用"——单卡 3-7 人天,现在就能做
   - **M2b**:力跨本体迁移——公开数据不够,DexUMI 双手小规模是唯一现成起点
2. **这个缺口本身是产品机会,也是风险**:
   - 机会:"带力+跨本体"数据没人有 → 若我们能采,就是真稀缺
   - 风险:正因为没人验过,**"力可跨本体"可能根本不成立**,而整个产品押在它上面
3. **DexUMI 的双手设置是最省的 M2b 起点**:它已经在 XHand 采、Inspire 测(带 FSR 力),
   虽小规模,但**是唯一能在公开数据上碰"力跨本体"的地方**——M2b 从它切入。

## 更新判决规则(比 README 原版更细)

- **M2a 若显示力无用**(与多篇矛盾)→ 先怀疑我的复现,再怀疑押注①
- **M2a 力有用 + M2b(DexUMI双手)力跨本体保留** → 押注①获得能拿到的最强公开证据,进 M3
- **M2a 力有用 + M2b 力跨本体丢失** → **最可能的坏结果**:力有用但绑本体 →
  产品必须改为"针对客户本体现采现标",不能卖通用力数据库。这直接改商业模式。
- M2b 因数据太小无法定论 → 这本身就是"为什么要造这个设备"的论据:**缺口=市场**
