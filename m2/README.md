# M2 · 跨本体力迁移验证(产品头号技术风险)

> PRODUCT.md 的 North-star 前提:手持采的力数据能不能提升 contact-rich 策略、
> 且迁移到客户机器人本体。**零生产级证据**,这是造设备之前就该用公开数据验的一条。

## 现状

- `ablation.py` — 力消融框架骨架,**已跑通并自证判别力**:
  - contact 世界(力携带信息):力增益同本体 +0.10、跨本体 +0.11(保留)
  - null 世界(力=噪声,对照):力增益 −0.01(正确识别力无用)
  - 由 `leg_ablation` 接入 gate:框架必须在 contact 世界报"力有用"、在 null 世界报"力无用",
    否则红。防框架退化为"给什么数据都说力有用"。

## 诚实边界(必须写清,否则是自欺)

1. **现在用的是合成数据**,只证明框架逻辑对。真结论必须换公开真机数据集
   (UMI-FT/ForceMimic/TacUMI/DexUMI 的开源数据——可得性由 M2 调查确认中)。
2. **用轻量分类器(RandomForest)代替真 VLA**。它测的是"力通道是否携带任务相关信息",
   不是"VLA 能否利用它"。关系是必要不充分:
   - 力连轻模型都提升不了 → 重模型多半也不行(**便宜的证伪,先跑这个**)
   - 力提升了轻模型 → 仍需真 VLA 复核(不充分)
3. **跨本体 gap 在合成里是"力标定尺度不同 + 分布平移"**。真实 gap 还含软硬顺应性差异
   (人手软指垫测的力 ≠ 刚性机器人指施加的力,见 route-02 未解难题 5),合成低估了难度。

## 接真数据的步骤(数据可得性已查,见 data-availability.md)

**M2 已劈成两半——头号风险恰好在验不了的那半:**

**M2a「力有没有用」——公开可做,现在就做:**
1. 首选 **RDP(Reactive Diffusion Policy)**:数据+代码+模型+mini 四要素齐全,MIT,单卡可跑
2. 次选 **DexUMI**:唯一自带 `enable_fsr` 力开关,离线可切"含力/关力"
3. 抽取特征替换 `make_task`;先跑"力连轻模型都提升不了吗"(便宜证伪),过了再上真 VLA
4. 多篇已一致正向(FILIC +33~53pp、ForceMimic +54.5%)——复现主要是给自己上出生证

**M2b「力能否跨本体」——硬缺口,公开数据不够:**
1. 最大跨本体数据(RDT2 UMI-10k / FastUMI-100K / OXE)**全是纯视觉无力**,不能用
2. 唯一"带力+跨本体"是 **DexUMI 双手**(XHand 采 / Inspire 测,带 FSR)——小规模,从它切入取弱信号
3. **强证据必须自采带力的跨本体数据**——这把"要不要造设备"和"最大风险能不能消除"绑成同一件事
4. 缺口本身是市场:没人有这数据 = 这正是设备要采的稀缺物

## 判决规则(先写死,不许事后改)

- 真数据上,力的同本体增益 Δ ≤ 0(或不显著) → **押注①作废**,退回纯质检 UMI
- 力同本体提升但跨本体增益 ≤ 0 → 力有用但不可迁移 → **只能卖"针对客户本体现采"**,不是通用数据
- 力同本体+跨本体都显著提升 → 押注①成立,进 M3 pilot 用真 VLA 终验
