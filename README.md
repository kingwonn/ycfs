# YCFS · 言出法随

> **一套 AI-native 的工程操作系统。**
> 人立法 · AI 执行 · 验证器裁决 · 现实仲裁。
>
> 「言出法随」——人说出的意图落成一张带**机器可查验收**的卡;卡的验收通过,工作才算存在。人只在三个门禁上签字,其余全部放权给 AI。

这个仓库沉淀的是一套在真实生产项目里跑出来的方法论(一个审计级经营报表系统,累计 70+ 轮自治迭代)。它回答一个具体问题:**当模型强到可以连续自主工作很多轮,人该怎么参与,才能既不失控、又不变成瓶颈?**

---

## 一、为什么需要它

模型越强,一次能做的工作越多;一次做得越多,它遇到的**未知**(你的意图与真实代码/世界之间的差)就越多。传统做法有两个失败模式:

- **管太细**:你把每一步都写死,AI 变成昂贵的补全,它比你更懂的地方全浪费了。
- **管太松**:你只说一句"帮我做个 X",AI 按行业默认猜,猜错的方向你事后才发现,回退很贵。

YCFS 的答案:**把"判断工作是否成立"这件事,从人的主观感受,搬进机器可查的验证器。** 人退到只做三件机器替不了的事——立法(说意图)、守数据红线、批对外动作。中间所有"做—验—提交—记录"由 AI 自转。

核心信条一句话:

> **地图不等于领土。** 你给 AI 的提示词、上下文、规范是地图;工作真正发生的代码库、现实、约束是领土。二者的差就是未知。方法论的全部功夫,是在修正代价变贵之前,尽早、廉价地发现未知。

## 二、三个角色

| 角色 | 职责 | 出现在哪 |
|---|---|---|
| **人(立法者)** | 说出意图;在三个门禁签字;在元层质疑评估本身 | 对话、`GATES/PENDING_HUMAN.md` |
| **AI(执行者)** | 意图→卡→做增量→跑验收→提交→写一行摘要 | 每轮 loop |
| **验证器(裁决者)** | 决定工作是否存在 | 每张卡的"验收"字段 + `gate` |

现实是第四个、也是最高的裁决者:**评估不闭环于评估者,闭环于现实。** 上线后的真实流量、真实买家、真实事故,才是评估对错的最终仲裁。

## 三、主循环

```
人说一句话(任何形式)
  → 当值 AI 落成一张卡:记录原话 + 翻译成任务 + 定义机器可查的验收
  → loop 轮转:选最高优先 ready 卡 → 做一小块可验证增量 → 跑验收
  → 通过:提交(工作分支,不碰 main)+ DIGEST 追加一行
  → 不通过:修复重试;卡在需要人的东西 → 标 blocked-on-human + 写进 GATES,换下一张卡
  → 人任何时候只需读两样:DIGEST(每轮一行)与 GATES(等签字的事)
```

关键:**没有时间线,只有优先级、依赖、验收。** 计划是一叠卡,不是甘特图。卡的顺序体现优先级,做完一张选下一张。

## 四、人只出现在三个门禁(其余全部放权)

| 门禁 | 触发 | 机制(机器可查,非口头) |
|---|---|---|
| **方向** | 战略选择 / 开新 lane | 卡标 `gate:direction`,人未批不动;`PENDING_HUMAN.md` 清单 |
| **数据** | 触碰 PII / 非本项目资源 / 任何不可逆操作 | denylist 命中即硬停;逐一具名确认,**概括式授权("都删")无效** |
| **对外** | 发送 / 发布 / 花钱 / 生产切换 | 状态机上**结构上不存在**绕过人审的边;对外产出一律先 `pending_review` |

这三个门禁之外,AI 全权自转。一个健康的 loop,人每天读几行 DIGEST、偶尔在一个 gate 上签个字。

## 五、验证器是分层的(YCFS 的技术核心)

「工作是否成立」不是一个布尔值,是一条纵深防线。以一个"每个对外数字都要可信"的系统为例:

| 层 | 守什么 | 时机 |
|---|---|---|
| **L0 真值编译** | 人工基线 → 断言集;真值有出生证(谁、何时、被谁接受) | 建库时 |
| **L1 出口零编造** | 每个对外数字必须溯源到真源,溯不到即硬阻断 | **每次请求** |
| **L2 发布前门禁** | 一条命令 N 腿全绿 + 预览环境三检才允许促升 100% 流量 | 每次发布 |
| **L3 持续在线** | 夜检探针对生产抽样,落红绿墙 | 每天 |
| **L4 覆盖增长** | 出题 → 候选 → **人审** → 机器 0 容差比对 → 断言集扩容 | 持续 |
| **L5 语义裁决** | 数字对但"答非所问"由异模裁判抓(裁判与被测物理分离) | 持续 |

两条贯穿全层的铁律:

1. **门槛只紧不松。** 验收阈值只能往严了改,永不为"凑过"放宽。放宽验证器 = 自欺。
2. **被测不能自证。** L4 晋级的真值锚不能是被测系统自己的输出;L5 的裁判不能是被测同一个模型;人核不能由 AI 冒充。**当自证通道打开,污染开始复利。**

详见 [docs/verifier-six-layers.md](docs/verifier-six-layers.md)。

## 六、先发现未知,再写代码

最有价值的一轮,往往不写任何实现代码。在动手前,用几种廉价手段把未知逼出来(方法出自 Thariq 的 *A Field Guide to Fable*,YCFS 把它内化为常规步骤):

- **盲点扫描**:让多个互盲视角(代码领土 / 行业 SOTA / 买家领土 / 对抗红队 / 方法论)并行找"未知未知",各自带证据,再合成一张**四象限未知地图**(已知已知 / 已知未知 / 未知已知 / 未知未知)。
- **访谈**:把未知提炼成问创始人的问题,**按"答案会改变架构"的程度降序**——先问那些答错就得推倒重来的。
- **参考**:说不清想要什么时,最好的规范是源代码——指给 AI 一个你喜欢的实现,让它复现语义。
- **测验**:长任务结束后,让 AI 拿这次变更考你,考过了才合并。读 diff 只给你浅层理解。

一个真实教训:上面那套验证器,五个视角的盲点扫描发现"最强结论只是复刻了旧系统某次凌晨的脚本输出"——直到一次架构级访谈才确认"这些数字历史上真发给过下游并被接受"。**一次访谈,省掉一次推倒重来。** 详见 [docs/finding-your-unknowns.md](docs/finding-your-unknowns.md)。

## 七、每个评估自带证伪条件

任何一个承重判断("这条路推迟做"、"这个风险可接受")都必须声明:**什么可观察的现象会证明它错**,以及错了的回退成本。说不出证伪条件的评估,不配被信。

```
判断:观测套件推迟(现在没人看仪表盘)
证伪条件:出现第一个需要按 SLA 回答"为什么慢/为什么错"的外部用户
回退成本:低——设计在库,拿出来就建
```

这让评估闭环于现实,而不是闭环于评估者的自信。一个观察到的元层事实:在那个真实项目里,**几次重大纠错全部由人的对抗性提问触发,而非 AI 自查**。结论:这套体系里,人的最高价值不是审批 gate,是**在元层持续质疑评估本身**;系统的义务是把每个评估写得足够短、足够可证伪,让质疑有的放矢。

## 八、派发纪律(事故换来的)

多 agent 协作里踩过的坑,全部编码成硬规则,而不是靠"记得":

- 派发提示必含"**禁止后台化,你就是执行者**"(多次自我后台化事故换来的)。
- 子 agent 工作目录固定仓库根;免读长文档;网络类验收主循环亲跑;超时无产出即改派。
- **前提变化触发重审**:继承来的文档,约束整体信、事实逐条验、决策在前提变化处重推。
- 提交前跑密钥扫描硬停;模型署名(谁产出谁署名);不可逆动作前备份验非空。

## 九、怎么把它用起来

YCFS 不是框架,是一组约定 + 几个可查的文件。落地只需要:

1. 一个 `BACKLOG`(卡:原话 + 翻译 + 机器可查验收 + 状态 + 依赖)
2. 一个 `gate`(一条命令跑全部验收,任一腿红即退出非零;门槛只紧不松)
3. 一个 `DIGEST`(每轮一行:做了什么 / 验收结果 / 卡点)
4. 一个 `GATES/PENDING_HUMAN`(等人签字的事)
5. 一句 loop 提示词(自包含:选卡→做增量→验收→提交→写摘要→报卡点)

模板见 [templates/](templates/)。把它们放进任何项目,配一个能跑循环的 AI agent(如 Claude Code 的 `/loop`),就跑起来了。

---

## 名字

**言出法随**——话说出口,法度随之成立。在这里:人说出意图(言),它当即落成一张有机器验收的卡、一条不可绕过的规则(法),AI 与验证器随之执行(随)。不是 AI 替人做决定,是人把"什么算做对了"写成机器能裁的法,然后放手。
