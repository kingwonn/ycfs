# 技术雷达 2026:哪些新进展能帮「言出法随」落地

> 调研于 2026-07。方法:8 个互盲视角并行调研(长时程自治 / 确定性验证 / 可扩展监督 / 出口接地 / 意图规范 / 编排协议 / 评估校准 / 门禁工效),每个视角由物理分离的敌对验证员逐条审查(是否真新 / 映射是否成立 / 成熟度是否虚标),只采信过审条目。剔除 2 条映射错配,订正 7 处事实与成熟度错误。凡无法独立核实的,标「未核实」。
>
> 这份雷达本身按 YCFS 纪律生产:研究员与验证员互盲、保守偏置(拿不准判弃)、每条带诚实 caveat。

---

## 一、一句话总纲

这波进展把 YCFS 的**执行层**推向成熟——延长自治半径、把确定性裁决器与出口核验器做成现成件、把门禁做成协议/分支保护/权限 hook 的结构性拦截;但它**触不到 YCFS 的三块硬核**:真值的出生证、被测不能自证、以及人在元层质疑评估本身。

> 技术在快速降低"廉价发现未知"的传输成本,却没有、也不会替你解决"未知是否被发现、真值是否为真、裁判是否独立于被测"——这三件恰是两条铁律与三门禁里人必须亲自兜底的部分。

## 二、进展地图(收敛为四块)

### 块 A|延长自治半径的持久化层(对应核心张力 + 派发纪律)

| 进展 | 成熟度 | 命中 YCFS | 可落地一步 |
|---|---|---|---|
| Anthropic 上下文编辑 + 记忆工具 | 厂商公测(非稳定 GA) | 主循环持久化层,撑过更多轮不撞窗口 | BACKLOG/DIGEST 落记忆文件,每轮清旧工具输出——**但记忆只当草稿,真值锚锚回外部** |
| Claude Agent SDK + orchestrator-worker 子 agent | 生产就绪 | 派发纪律的 harness;上下文隔离=子 agent 只回传相关;权限=三门禁结构化 | 把派发纪律编码进权限 hook 与子 agent 系统提示 |
| METR 任务时长地平线 | 研究 | 核心张力的度量仪 | 按**约 80% 可靠度(非 50% 头条)**地平线给 lane 定尺,超限即拆卡或加方向门禁 |
| Context Rot(Chroma 2025) | 研究 | 给长自治划静默上限,支撑 L3 与周期人门禁不可裁撤 | 每 lane 设远低于窗口的硬预算(约 30-50% 即压缩);"长期未压缩历史"本身列为证伪条件 |

**两条敌对验证的订正,分量不亚于进展本身:**

1. 厂商宣称的收益(84% token 降、+90.2% 多 agent 增益、"100 轮跑完")全部出自厂商自家 bench、很可能同族裁判,**无一在你的仓库验证**。叙述框架必须是"厂商在自家 bench 上宣称 X",不是"解掉了 X"。
2. 头条自治时长(7h、25h 单跑;更长的报道未核实)是**峰值 demo,不是可靠性**。按 YCFS,一次超长无人跑恰恰把"做越多、未知越多"拉满、把发现未知推到最贵处——这些数字进危险栏的分量不亚于进进展栏。

补充值得跟踪:生产级自动开 PR agent(Copilot / Cursor / Devin——对外门禁问题的活体)、可靠性度量(Terminal-Bench、SWE-bench Verified、pass^k)。

### 块 B|把裁决从「LLM 说了算」搬到确定性检查器(对应 L0/L1/L2)

**通用模式,比任何单一技术都重要:**

> **独立、确定性的检查器 + 提议/处决分离**——被测提议,外挂的确定性裁判处决。这是"AI 验 AI 不违反铁律②"的唯一合法形态。

| 进展 | 成熟度 | 命中 YCFS | 关键 caveat |
|---|---|---|---|
| AWS Cedar:Lean 规范 + 差分随机测试 | 生产就绪 | L0(带机器证明出生证的真值源)+ L2 差分测试腿 + 铁律② | 差分测试只证"一致"不证"正确";规范与实现同错=自洽的错误(自等式陷阱) |
| LLM 出题的 property-based testing / fuzzing(OSS-Fuzz-Gen 等) | 新兴 | L2 门禁腿 + L4 出题引擎;**oracle 确定性、LLM 只出输入不裁对错** | 最危险失效=让 LLM 写 oracle;研究显示 LLM 仅能为约 1/5 API 合成健全性质,L4 人审题不可省 |
| Bedrock Guardrails 自动推理校验 | 生产就绪(GA 2025-08) | L1 规则域确定性门;用求解器而非 LLM 裁决 | soundness 只相对"你写的策略";**NL→形式规范的编译步骤本身没上门禁、无出生证——地图≠领土的缝被搬进编码器,没被消除**;99% 是 AWS 自评 |
| Lean 神经定理证明(DeepSeek-Prover-V2、AlphaProof 等) | 新兴 | L0:机器已验=可能最强的出生证;内核处决 | 要保留的是"内核处决"模式,不是 Lean 的光环;88.9% 是 pass@8192 附巨大搜索预算 |
| AI 辅助可验证代码合成(Verus、Dafny;VERINA 基准) | 新兴 | L2 可执行规范腿 + SMT 确定性裁判 | `assume false` / 写错规范即开自证通道;当前 AI 远未能稳产健全 spec+证明 |
| 确定性仿真测试 DST(Antithesis、TigerBeetle VOPR) | 成熟技术获采纳动能(**非新发明**,FoundationDB 2015 起) | L2 整体跑 + L3 重放确定性;种子=证伪条件,重放=回退近零 | 2025-2026 新的只是融资与生态采纳 |
| 约束解码 / 结构化输出(XGrammar、Structured Outputs strict) | 生产就绪 | L1 出口"格式合规硬阻断"的最直接确定性门 | **只保证 JSON 的"形",不保证字段里数字的"实"**;有推理"对齐税" |
| **数字域确定性核验**(计算器 / 代码解释器 / SQL 对源核对) | 生产就绪 | **L1"数字走确定性、LLM 永不拿数字最终裁决权"的真正落地手段** | 初版调研的最实质漏项,由敌对验证补入;实现平凡,纪律不平凡 |

### 块 C|用 AI 监督 AI 而不打开自证通道(对应 L4/L5 + 铁律②)

这是 YCFS 里唯一"AI 裁 AI"的地方,也最需要按铁律②反复点破。整体地基是 2024(Prover-Verifier Games、GenRM、辩论实证),**2025-2026 是其上的延伸测量,不是新突破群**。

| 进展 | 成熟度 | 命中 YCFS | 采纳时的铁律约束 |
|---|---|---|---|
| Prover-Verifier Games + 弱到强 legibility | 研究 | L4/L5:强模型输出须能被更弱一方独立核验 | 可在 L2/L4 加"可读性门":小验证器复核不了即判红。同族自训样本=违反铁律② |
| 生成式验证器 GenRM 及后继 | 新兴 | L5 输出书面批注入库作出生证 | 常用同族自生成 critique=自证;"再叠一个 meta 校验器"只有真异族、真值锚在被测外才不违规 |
| LLM 裁判自偏好偏差量化 | 新兴 | L5"异模"与"校准需真人盲标"的实证背书 | "越强越自恋"未定论(有研究示自偏好与能力不强相关);方向性现象足以支撑铁律②。**面板聚合必须取最严,取平均会把红票洗绿=违反铁律①** |
| 辩论(经验 + doubly-efficient) | 研究 | L5 对抗版,天然出题/被测/裁判分离 | **说服力≠真值**:自信而错的模型可能赢下辩论;疑罪从红 |
| 过程奖励模型 PRM | 新兴(仅数学/代码窄域) | L4 在最便宜的步设锚 | 教训即铁律②警报:用被测自身 rollout 造标签=真值锚落回被测。锚必须人标/异源 |
| 自动化对齐审计(Petri、SHADE-Arena 等) | 新兴 | L3 主动对抗诱发;审计员≠被测 | 审计员也是 LLM:有盲区、被测可 sandbag、同族即重开自证。补充,非真值预言机 |
| LLM-as-judge 统计严谨性(一致率带置信区间) | 生产就绪 | L5 校准:一致率须带 95% CI + 聚类标准误(聚类 SE 可比朴素大 3 倍) | **CI 下界跌破阈值才判退化**;judge 一致率必须对 human-human 一致率(κ/α)归一化,否则"92%"可能已触人锚噪声上限 |
| LiveBench 式免裁判评测 | 生产就绪 | 月度刷新 + 客观真值自动判分 = L0 出生证 + L4 抗污染 + 免自证的可抄范本 | 只在有客观真值处成立 |
| The Leaderboard Illusion | 诊断/审计 | 反面教材:被测对着裁判梯度上升(私测多变体择优)踩穿 L4 红线 | **不用公开 leaderboard 分作 L0 真值锚** |
| RLVR 脆弱性(Spurious Rewards) | 研究 | **"可验证≠不可游戏"** | 接任何自动验证器进 gate 前,先对它做"格式对但内容错/提前泄答案"的对抗测试 |
| AI Control 议程(Redwood / Anthropic control evals) | 新兴 | 可信弱监控器闸门不可信强执行器;"不信被测已通过"=门禁自跑门禁 | 敌对验证点名的最该补线:与 YCFS 同构度最高的安全议程 |
| CoT 可监控性 + 隐藏目标审计 | 研究 | 不靠被测自我报告去监督被测——正面回应最硬问题 | 多实验室立场:可监控性是脆弱资源,训练压力可令其消失 |

|---|---|---|---|

## 三、优先采纳路线图(边际价值 × 落地成本,前五)

> 卡片纪律:每项写清接哪一层 + 机器可查验收 + 证伪条件。禁止收录无法派生确定性测试的验收。

**① 对外单点 + deny-by-default 权限/hook 层** ——接 L1 / 对外门禁(价值最高、成本最低、本地零依赖)
- 验收:所有 send/publish/deploy/spend **静态可证只经单一 choke-point 函数**;权限 deny-by-default,新增出边默认拒;绕过尝试在 CI 报红退非零;**禁用任何 auto-timeout 自动放行**。
- 证伪条件:存在一条到生产/外发、不穿过该函数的路径 → 门禁形同虚设。回退成本近零。

**② 生成者 ≠ 批准/合并者 分支保护不变量** ——接对外门禁 + 铁律②(存在性已被 Copilot 证明)
- 验收:分支保护禁止 PR 作者身份=合并者身份;agent 身份无 merge 权;提交前密钥扫描硬停。
- 证伪条件:任一变更能由生成它的同一身份批准/合并/部署 → 自证通道开。

**③ L1 出口双门:确定性数字校验 + 异模蕴含核验** ——接 L1(填补最实质漏项)
- 验收:每个对外数字与确定性重算(代码/SQL 对源)不符即硬阻断,LLM 拿不到数字最终裁决权;每条对外承重句+溯源 chunk 喂本地异模核验器,低于阈值→PENDING_HUMAN;property-based 对抗集 N 条篡改必全判红、N 条真值零误伤;阈值只紧不松。
- 已知副作用:NLI 核验器高召回、低精度,会过度阻断真内容——**为降误阻而调松阈值正是铁律①陷阱,宁可误阻退人审**。
- 证伪条件:检索给错源时核验器会忠实确认错误接地 → "给对源"不在本门覆盖,须靠 L0。

**④ EARS 验收字段 + strict schema 门禁** ——接 L0/L2 卡验收(成本低)
- 验收:BACKLOG 卡验收字段必须 EARS 句式(`当<可观测触发>,系统应<可确定性检验的响应>`)且能派生确定性测试,否则拒收;**人对 EARS 条款签字后才作真值锚**(禁止 AI 自生成 EARS 再自派生测试);对外结构化产出走 strict schema,可枚举域钉进 enum,校验失败退非零。
- 证伪条件:一条格式完美的 EARS 编码了错误意图 → schema 只保证"形",意图对错仍须人审。

**⑤ L5 校准统计化 + human-human 归一化** ——接 L5(成本中等)
- 验收:judge-真人盲标一致率=点估计 + 95% CI + 聚类标准误;CI 下界跌破阈值才判退化;一致率对 human-human 一致率归一化;翻案率(换位/异家族复判)作必要不充分红旗,绝不替代真人盲标;面板聚合取最严。
- 证伪条件:换个顺序或换个长度判决就翻 → 该判决不承重,退人审。

## 四、诚实的「仍未解」——技术再进步也不替 YCFS 解决的

1. **真值的出生证(L0)**:没有任何模型能自动填"谁编/何时/被谁接受/错误率"。Bedrock 类系统把 NL→形式规范的编译步骤本身没上门禁——地图≠领土的缝只是被搬进编码器,没被消除。凡把真值锚落到被测自己身上,污染复利。
2. **规范↔意图的正确性**:EARS/Spec Kit/TLA+/形式验证全都只能查"代码是否符合 spec",**永远查不了"spec 是否符合人的真实意图与现实"**。一条错的形式命题也能被"证明"。这条差从代码层搬到了规范层,没有消失。
3. **数字最终裁决**:语义熵类幻觉检测是被测对自己采样算方差=自证,只抓"模型自己都不确定"的编造,**对自信而一致的胡说完全失灵**——而这类最危险。数字必须彻底离开语义模型。
4. **说服力≠真值**:辩论、GenRM、LLM 裁判都在优化"更能说服弱裁判",无一保证胜出=正确。
5. **全行业裁判共有偏差**:异模、跨家族、meta-judge 都只在 AI 内部互相制衡,挡得住 self-preference,挡不住前沿模型训练数据高度重叠带来的共同品味偏差(偏长、偏客气、偏自信)。**只有真人盲标能跳出这个圈。**
6. **长时程"跑对多久"**:80%+ 可靠度地平线远短于 50% 头条;模型会连跑数小时却静默退化。技术能拉长"跑多久",不能保证"跑对多久"。
7. **三门禁背后的价值判断**:方向、数据红线、不可逆授权的问责,没有任何可扩展监督技术能代偿。协议给的是载体(elicitation 可选可绕),不是约束。
8. **未知的未知**:PRM/审计/DST/fuzz 只能测已想到的失败模式;差分测试证"一致"不证"正确",fuzz 证 bug 存在不证不存在。这一层靠人立法时的证伪条件设计与现实仲裁兜底。

## 五、一条元层警告

**这波进展最容易让人放松警惕、从而违反铁律的陷阱,是"用更多、更好用的 AI 层去查 AI",把被测自证包装成解药。** 它有两副面孔:

- **数字面孔**:"production-ready"、84% token 降、+90.2%、99% 准确率、7h/25h 自主跑——全是厂商自家评测、很可能同族裁判、从未在你的仓库验证过的数字。一旦把其中任一个静默晋级成真值锚,你就正好做了那些 caveat 反复告诫的事。凡引用,叙述框架应是"厂商在自家 bench 上宣称 X",不是"解掉了 X"。
- **舒适面孔**:grader 扇出的"一句干净裁决"、reviewer 把 12 条争论摘要掉、按需加载的裁剪——这些为人的舒适而优化,与"尽早暴露未知"相反。**让审阅工效化的摘要,与埋葬未知的摘要,是同一个摘要。**

判据只有一条,且技术永远不会替你自动遵守:**每一处"让 AI 写验证器/规范/oracle/critique/grader/记忆/真值锚"的捷径,都重新打开自证通道;工具越好用、越丝滑,这条通道越隐蔽。** 守住它的不是任何进展,而是把"裁判≠出题≠被测、rubric 服务端固定、校准要真人盲标、门槛只紧不松"写进结构、并由人在元层拒绝自欺。技术把人从"做-验-提交-记录"里解放出来,但没有、也不该把人从三门禁与证伪质疑中移走。
